# 卡顿/缓慢，甚至无响应/死机/崩溃.

此类问题涉及范围很大，且问题来源可深可浅，不建议一股脑将所有猜测塞给客户，需要耐心逐步排查。

通常可能是负载较高引起的，以下是可能可能产生较大的负载的进程：

- RAID 同步，您可以等待 RAID 同步完成。如果您还能访问 TOS 网页-控制面板，您可以考虑降低 RAID 同步速度。
  
- 缩略图生成，通常发生在您写入大量的视频/图片文件后，需要较长时间来为新视频/图片生成缩略图以方便后续使用。
  
- Docker 容器：容器的负载占用情况可能无法被系统监测到，建议您限制好 RAM 的占用。
  
- 下载工具：qBittorrent、Trasmissionm、Aria2... 可能由于传输任务过多引起网络带宽和 DiskIO 占用过高。
  
- Jellyfin，
  
- 传输任务，
  
- 虚拟机，
  
- 等...
  

建议您控制好性能开销。可以通过在终端使用常用 Linux 指令

检查是否有任何因虚拟机、Docker、下载工具等 APP 的误操作而将文件放入系统根目录导致爆满的情况：


```bash
df -h
```

文件系统故障或 HDD 故障，导致读写异常。建议检修文件系统和检查 HDD 健康情况。
