# 在TOS6中, smbrichacl 负载(内存占用)高.

**关键词：SMB**

**解决方案：**

原因：smbrichacl是SMB权限赋权进程，负责将新修改的权限应用到所作用的文件上。

说明：
- 当您近期对大量文件或用户做了权限修改时，smbrichacl会占用较多资源来完成权限覆盖
- 这是正常行为，权限应用完成后资源占用会下降

处理方法：
1. 耐心等待：权限覆盖任务完成后，smbrichacl占用会自动降低
2. 减少权限修改范围：避免一次性对大量文件修改权限，建议分批操作
3. 低峰期操作：在系统负载较低时修改权限，减少对正常使用的影响
4. 若持续高占用：检查是否有异常进程，或重启SMB服务（TOS Web > 控制面板 > 文件服务 > SMB > 重启服务）
