# 🔗 R6 架构解耦专项方案

> 上游依据：[05 报告](05-架构健康度诊断与迁移计划.md) 目标架构「端口-适配器」总纲；[06 R5 专项](06-R5白名单清理专项方案.md) 已完成资源域解耦，本专项收口**模块依赖域**的残余耦合。
> 执行原则：只解耦有实证的耦合点；经评估无收益的拆分明确记录「不执行」及触发条件，防过度工程。每阶段独立可回滚。

## 一、背景与目标

R5 专项解决了**资源**层的外链依赖；本专项审计后发现**模块依赖**层仍有 3 处实证耦合 + 1 处规范债：

| # | 耦合点 | 违背的原则 |
| ---- | ---- | ---- |
| 1 | api 层硬连线遥测 | 端口-适配器一致性：同一文件内 SnapshotStore 已端口化可注入，遥测却是 `import { recordEvent }` 直连 |
| 2 | auth 切换器第二页面事实源 | 单源注册：registry 已是 43 项编译期完备的页面清单单源，App.tsx 又硬编码 10 项 auth 按钮 |
| 3 | renderContext 无显式类型约束 | 失配早报错：`RenderContext` 增字段时错误延迟到 43 个 render 调用点 |
| 4 | useApiData 依赖数组收窄 | 规范化：`eslint-disable-next-line react-hooks/exhaustive-deps` 压制而非修复 |

**目标**：api 层 0 个横切依赖导入（新门禁 R8 校准 0 违规）；页面清单全仓唯一事实源；`eslint-disable` 清零；79 tests 保持全绿。

## 二、现状盘点（2026-10-11 实测）

### 2.1 耦合点 #1：api → observability 硬连线

[useApiData.ts](../../src/api/useApiData.ts) L27 `import { recordEvent } from '../observability/telemetry'`，共 4 处调用（L74 快照写入失败 warn、L86 降级读快照 warn、L89 快照解析失败 warn、L94 请求 error）。配套测试 [useApiData.test.ts](../../src/api/__tests__/useApiData.test.ts) L19 直接 `import { clearTelemetry, getRecentEvents }` 断言**全局环形缓冲**——测试与全局单例状态纠缠，并行跑存在相互污染隐患。

对照同一文件：`SnapshotStore` 端口（L39-49）+ 默认适配器 + 测试注入内存实现（`createMemoryStore`）——遥测是同文件内**唯一没走端口模式的出边**。

### 2.2 耦合点 #2：App.tsx auth 切换器（第二事实源）

[App.tsx](../../src/App.tsx) L125-195 硬编码 10 个 auth 按钮（A01登录…A09锁定）。实测 [registry.tsx](../../src/navigation/registry.tsx) L233-269 的 REGISTRY auth 键序为 `login→register→forgot→reset→mfa→invite→onboarding→expired→403→locked`，与按钮顺序**完全一致**——可安全派生。风险实质：新增 auth 页面时 registry 编译期强制注册，但切换器按钮会**静默缺失**（不报错、不可见、无门禁可拦）。

### 2.3 耦合点 #3：renderContext 裸对象

[App.tsx](../../src/App.tsx) L99-106 `const renderContext = { navigate…, openCognition… }` 无 `satisfies RenderContext` 标注。`RenderContext`（registry 导出）增字段时，类型错误将在 43 处 `getPageEntry().render(renderContext)` 调用点报出而非定义点——错误定位劣化。

### 2.4 耦合点 #4：useApiData 压制的依赖数组

[useApiData.ts](../../src/api/useApiData.ts) L100-102 注释 + `eslint-disable-next-line react-hooks/exhaustive-deps`，依赖数组仅 `[loader]`。`options.snapshotKey`/`options.snapshotStore` 变更不触发重载（当前调用点均为字面量常量，无实际 bug，属规范债）。

### 2.5 明确不执行项（决策记录，防过度工程）

| 候选项 | 评估结论 | 复启触发条件 |
| ---- | ---- | ---- |
| services.ts 按域拆分（仿 data/types） | **不拆**：9 服务约 110 行单文件，拆分后 barrel+多文件的 churn 收益比为负；与 data（508 行）/types（多域混居）拆分时的体量完全不同量级 | 服务数 >15 或单文件 >300 行 |
| registry.tsx 按域分段（6 segment 文件） | **不拆**：43 项单文件约 270 行，同源注册（meta/render 同模块引用）的可见性收益 > 分段的冲突规避收益；[registry.test](../../src/navigation/__tests__/registry.test.tsx) 43 项全遍历已护航 | 页面数 >60，或出现实际合并冲突 |
| 43 页 StandardPageProps 统一接口 | **不拆**：各页 props 已是结构化子集，类型等价的纯机械改动 | 新增页面批量接入时顺势统一 |

## 三、方案选型（R6-A 遥测端口形态）

| 形态 | 做法 | 裁决 |
| ---- | ---- | ---- |
| **a. 模块级 sink + 组合根注册** | api 层定义 `ApiEventSink` 类型 + 模块级默认 no-op + `setApiEventSink()`；main.tsx 组合根注入 recordEvent 桥接 | ✅ 行为等价（App 挂载前注册）、api 零 observability 导入、测试注入收集器摆脱全局环形缓冲 |
| b. 每调用点传回调 | `useApiData(loader, { onEvent })` 可选参数 | ❌ 全仓 20+ Hook 调用点逐个传参，churn 大且每个调用点可遗忘 |

形态 a 与既有 `SnapshotStore` 模式对齐（端口默认适配器 + 可注入），仅注册时机从「调用点参数」变为「组合根一次性」——因为遥测是横切关注点而非按调用点差异化的关注点。

## 四、分阶段执行步骤

### R6-A 遥测端口化（api → observability 依赖倒置 + 新门禁 R8）

**目标**：api 层 0 observability 导入；遥测行为不变；测试与全局环形缓冲解耦。

**操作**：
1. [useApiData.ts](../../src/api/useApiData.ts)：新增导出（置于 SnapshotStore 定义之后）：

```ts
/** 遥测事件端口 — 组合根（main.tsx）注册，api 层不直接依赖 observability */
export type ApiEventLevel = 'error' | 'warn' | 'info';
export type ApiEventSink = (level: ApiEventLevel, source: string, message: string, detail?: string) => void;

let apiEventSink: ApiEventSink = () => {}; // 默认 no-op：未注册时零副作用
export function setApiEventSink(sink: ApiEventSink) { apiEventSink = sink; }
```

   4 处 `recordEvent(...)` 改为 `apiEventSink(...)`（**消息字符串原样保留**，签名与 telemetry.recordEvent 结构兼容）；删除 L27 导入。
2. [main.tsx](../../src/main.tsx)：组合根注册（`createRoot` 之前，确保任何页面请求前就位）：

```ts
import { setApiEventSink } from './api/useApiData';
import { recordEvent } from './observability/telemetry';

setApiEventSink((level, source, message, detail) => recordEvent(level, source, message, detail));
```

3. [useApiData.test.ts](../../src/api/__tests__/useApiData.test.ts)：删除 L19 全局遥测导入，`beforeEach` 注入收集器：

```ts
const events: Array<Parameters<ApiEventSink>> = [];
beforeEach(() => { events.length = 0; setApiEventSink((...args) => events.push(args)); });
```

   原对 `getRecentEvents()` 的断言改为对 `events` 的断言（事件内容不变，仅读取来源变化）。
4. [check-boundaries.mjs](../../scripts/check-boundaries.mjs)：新增规则 **R8 api-no-observability**——`src/api/`、`src/domain/`、`src/tokens/`、`src/data/` 禁止导入 `observability`（observability 是被消费的横切层，只能被 UI 组合根与组件消费）；头部注释登记 R8。
   App.tsx / DevModeDrawer 消费 recordEvent/getRecentEvents 属组合根与 UI 读端，合法不在约束范围。

**验收**：
- [ ] `grep -n "observability" src/api/ -r` → 0 命中
- [ ] `pnpm check:arch` → R8 校准 0 违规（探针：临时在 api 文件加 observability 导入应报 R8）
- [ ] `pnpm test` → 79 passed（useApiData 事件断言改注入收集器后全绿）

**回滚**：revert useApiData.ts + main.tsx + 测试 + 门禁四文件，恢复直连（行为零差异，双向安全）。

### R6-B auth 切换器派生渲染 + renderContext 类型收紧（耦合点 #2/#3）

**目标**：页面清单回归单源；新增 auth 页面时切换器编译期强制同步。

**操作**：
1. [registry.tsx](../../src/navigation/registry.tsx) 末尾新增导出：

```ts
export type AuthPageId = PageId & `auth-${string}`;
export const isAuthPageId = (id: PageId): id is AuthPageId => id.startsWith('auth-');

/** auth 标签映射：映射类型过滤强制覆盖全部 auth 页面（新增 auth 页漏配 = 编译错误） */
const AUTH_LABELS: { [K in PageId as K extends `auth-${string}` ? K : never]: string } = {
  'auth-login': 'A01登录',
  'auth-register': 'A02注册',
  'auth-forgot': 'A03找回',
  'auth-reset': 'A04重置',
  'auth-mfa': 'A05双验',
  'auth-invite': 'A06邀请',
  'auth-onboarding': 'A07引导',
  'auth-expired': 'A08过期',
  'auth-403': 'A08-403',
  'auth-locked': 'A09锁定',
};

export const AUTH_PAGE_ITEMS: ReadonlyArray<{ id: PageId; label: string }> = PAGE_IDS.filter(isAuthPageId)
  .map((id) => ({ id, label: AUTH_LABELS[id] }));
```

2. [App.tsx](../../src/App.tsx) L126-188 的 10 个重复按钮 → `AUTH_PAGE_ITEMS.map(({ id, label }) => <button key={id} onClick={() => handleNavigate(id)} className={/* 既有三元原样 */}>{label}</button>)`（Dev Mode 切换按钮保留在 map 之外）。
3. 同文件 L99：`const renderContext = {...}` → `const renderContext = {...} satisfies RenderContext`（`import type { RenderContext } from './navigation/registry'`）。
4. [registry.test.tsx](../../src/navigation/__tests__/registry.test.tsx) 新增 1 用例：`AUTH_PAGE_ITEMS` 长度 === `PAGE_IDS.filter(isAuthPageId).length` 且逐项 label 非空、id 均在 REGISTRY 中（防标签映射漂移）。

**验收**：
- [ ] `pnpm typecheck` → 0 errors（映射类型强制：注释掉任一 AUTH_LABELS 条目应编译报错——手动探针验证后恢复）

## 五、风险与缓解

| 风险 | 等级 | 缓解 |
| ---- | ---- | ---- |
| R6-A sink 注册时序：注册前发生请求导致事件丢失 | 低 | main.tsx 在 `createRoot().render()` **之前**注册；页面请求只会由组件挂载触发，时序天然保证；验收项含行为等价实证 |
| R6-A 测试改造遗漏某条事件断言 | 低 | 4 处事件消息字符串不变，仅断言来源从全局缓冲改为收集器；79 基线中 useApiData 相关用例逐一核对 |
| R6-B 映射类型过滤语法兼容性（TS 5.7 as 子句） | 低 | 项目 TS 5.7 完全支持 key remapping（4.1+ 特性）；探针验证覆盖 |
| R6-B 派生顺序与现按钮顺序不一致 | 已排除 | 实测 REGISTRY auth 键序 === 现按钮序（A01→A09）；`PAGE_IDS` 保 Object.keys 插入序 |
| R6-C 引入重复请求/循环 | 低 | 依赖字段均为原始值或模块级稳定引用（browserSnapshotStore 常量）；Network 面板专项验收 |
