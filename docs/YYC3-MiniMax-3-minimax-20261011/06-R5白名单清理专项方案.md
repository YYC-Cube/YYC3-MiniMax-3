# 🎯 R5 外链白名单清理专项方案

> 上游依据：[05-架构健康度诊断与迁移计划](05-架构健康度诊断与迁移计划.md) 第五节 R5 规则、第六节门禁表「外链硬依赖」行；
> [03-总结文档](03-总结文档与状态同步.md) 遗留 TOP 1。
> 执行原则：先门禁红起来 → 迁移转绿 → 删白名单。每阶段独立可回滚。

## 一、背景与目标

**现状**：[check-boundaries.mjs](../../scripts/check-boundaries.mjs) R5 规则以 `EXTERNAL_URL_ALLOWLIST = ['images.unsplash.com']` 对演示图床全域豁免——src/ 内 49 处 unsplash URL 字面量不报违规。豁免理由是「运行时已由 Thumb 100% 降级覆盖」，但白名单是**宽口径**：任何文件新增任意 unsplash URL 都会静默通过，本地优先约束实际未闭环。

**目标**：`EXTERNAL_URL_ALLOWLIST` 置空后 `pnpm check:arch` 仍 0 违规；全站图片资源 100% 本地化（或确定性占位），断网/在线视觉一致。

**总原则**：图片断网降级能力（Thumb）已就绪，本专项解决的是**源代码对外链图床的字面量依赖**——与运行时体验无关，纯属架构卫生。

## 三、方案选型

| 方案 | 做法 | 优点 | 代价 | 裁决 |
| ---- | ---- | ---- | ---- | ---- |
| **B2 本地资产**（推荐主案） | 12 张照片下载至 `public/demo/{photo-id}.jpg`（w=600 统一尺寸），49 处 URL 改 `/demo/...` 本地路径 | 视觉完全不变；本地路径天然不触发 R5；离线在线一致 | 仓库 +600KB 二进制；需一次网络下载 | ✅ 主案 |
| B1 data URI（兜底） | URL 替换为确定性 SVG 渐变 data URI（与 Thumb placeholderTone 同源算法） | 零二进制；零网络依赖 | 演示照片变渐变卡片（在线视觉降级） | B2 网络不可行时兜底 |
| B3 白名单收窄（最保守） | 白名单仅对 `src/data/` 生效，页面层立即 0 豁免 | 改动最小 | 外链字面量仍存在于 data 域，「清理」不彻底 | 作为 R5-A 的过渡形态吸收 |

## 四、分阶段执行步骤

### R5-A 门禁两档拆分（先让页面层红起来）

**目标**：R5 从「全域白名单」改为「仅 data 域白名单」，页面层立即 0 豁免——现状即报 18 处违规，驱动后续迁移。

**操作**：
1. 修改 [check-boundaries.mjs](../../scripts/check-boundaries.mjs) R5 段：白名单命中条件追加 `inDir(rel, 'data')` 前置——

```js
// 修改前
if (!EXTERNAL_URL_ALLOWLIST.some((allowed) => host === allowed || host.endsWith(`.${allowed}`))) {
  add('R5-no-external-urls-in-src', rel, `外链 URL 不在白名单：${m[0]}`);
}
// 修改后：白名单仅对 data 演示数据域生效
const allowlisted = inDir(rel, 'data')
  && EXTERNAL_URL_ALLOWLIST.some((allowed) => host === allowed || host.endsWith(`.${allowed}`));
if (!allowlisted) {
  add('R5-no-external-urls-in-src', rel, `外链 URL 超出 data 域白名单：${m[0]}`);
}
```

2. 同步更新脚本头部注释 R5 说明与白名单注释（「待页面层清零后进一步收窄至空」）。

**验收**：`pnpm check:arch` → 恰好 18 处 R5 违规（全在 pages/），退出码 1。**此阶段门禁为红是预期状态**（驱动迁移），可与 R5-B 同一工作会话内完成红→绿，不留红门禁过夜。

**回滚**：revert 单文件改动即恢复全域白名单。

### R5-C 数据层本地化（31 处 → 0，方案 B2）

**目标**：12 张照片落库 `public/demo/`，data 域 31 处 URL 全部改为本地路径。

**操作**：
1. **下载资产**（一次性，需网络；沙箱受限则在宿主终端执行）：

```bash
mkdir -p public/demo
# 12 个 photo-id 逐一下载（示例两条，其余同理）
curl -sL "https://images.unsplash.com/photo-1534528741775-53994a69daeb?w=600&q=75&fm=jpg" -o public/demo/photo-1534528741775-53994a69daeb.jpg
curl -sL "https://images.unsplash.com/photo-1517841905240-472988babdf9?w=600&q=75&fm=jpg" -o public/demo/photo-1517841905240-472988babdf9.jpg
# …共 12 条，photo-id 清单见第二节 2.3
# 校验：12 个文件均为 JPEG 魔数（ff d8）
for f in public/demo/*.jpg; do xxd -p -l2 "$f"; done
```

2. **URL 替换**：data 三文件 31 处 `https://images.unsplash.com/photo-{id}?w={N}` → `/demo/photo-{id}.jpg`（尺寸参数丢弃，object-cover 承担缩放）。可用一次性 node 脚本或编辑器全局替换，正则：`https://images\.unsplash\.com/(photo-[0-9a-z-]+)\?\w+=\d+` → `/demo/$1.jpg`。
3. **兜底分支**（网络不可行时启用 B1）：改用脚本将 URL 替换为确定性 SVG data URI（复用 placeholderTone 色相算法），并在本文档记录「B2 未达，B1 兜底」。

**验收**：
- [ ] `grep -r "unsplash" src/` → 0 命中
- [ ] `ls public/demo/*.jpg | wc -l` → 12（B1 分支则跳过）
- [ ] Dev Server 断网模拟（DevTools Offline）刷新 → 全站图片正常显示（B2）或渐变占位（B1），无破图
- [ ] `pnpm build` → 产物含 demo 资产，主 chunk 不变（public/ 不入 chunk）

**回滚**：data 三文件 revert + 删除 `public/demo/` 目录即可；资产文件与源码改动互不纠缠。
