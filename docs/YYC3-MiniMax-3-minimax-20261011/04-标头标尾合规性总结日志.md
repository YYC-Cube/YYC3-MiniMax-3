# 📐 全局标头/标尾合规性总结日志

## 一、任务背景

依据《YYC3-团队规范-文档闭环.md》v3.1.0「标准化升级 — 统一文档标头标尾格式」与《YYC3-团队文档-引擎模版.py》元数据规范，对本项目工程文件执行全局标头/标尾合规化，实现**可追溯**（created/updated/checksum 式元数据）与**可迭代**（语义化版本自动递增）。

## 二、标准依据

| 文件类型 | 标头规范 | 标尾规范 |
| -------- | -------- | -------- |
| Markdown | YAML frontmatter（file/description/author/version/created/updated/status/tags/category 九键）+ 品牌块引标头 | 品牌块引标尾 + 「© 2025-2026 YanYuCloudCube™. All Rights Reserved.」 |
| 代码（ts/tsx/mjs） | JSDoc 元数据块（@file/@description/@author/@version/@created/@updated/@status/@copyright/@license，冒号格式，规范序） | —（版权信息在标头 @copyright/@license） |

## 八、经验教训

| 问题 | 教训 |
| ---- | ---- |
| 模板输出格式与解析格式不一致（无冒号 vs 冒号）导致重复注入 | 生成器与解析器的格式契约必须单点定义、双向对齐 |
| 字符串切片插入破坏闭合行缩进 | 结构化文本插入应按行定位（findIndex + splice），不做偏移敏感的切片拼接 |
| description 从首个 `# ` 行提取误中代码围栏内 shell 注释 | 提取语义信息前先剥离 ``` 围栏与 HTML 注释，并优先 `<h1>` |
